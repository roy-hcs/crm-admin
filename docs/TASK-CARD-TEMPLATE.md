## 1. 每批唯一需要人填的东西

### 1.1 覆盖表（发给 flash）

| 组  | 被测函数 / 文件 | 必须覆盖的边界（最低集） | 落盘文件 / project |
| --- | --------------- | ------------------------ | ------------------ |
|     |                 |                          |                    |

> 边界只增不减；oracle =
> **当前实现的可观测输出**，不是旧版模板 / 产品口径（清单 §3 拍板 B）。期望值先读实现推导，回执写「输入 → 期望 → 实现文件:行号」，禁止编（R-8）。

### 1.2 JSON 差值（`scripts/verify-<batch>.json`）

从上批配置复制，只改这些键：

| 键                                       | 填什么                                                                                                                                                    |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `batch` / `expectedHead`                 | 批次号；HEAD 通常不变                                                                                                                                     |
| `expected.{testFiles, tests, domMarker}` | 本批预期文件数 / 用例数 / dom project 归属标记（注意 stripAnsi 后是**两个空格**）                                                                         |
| `expected.{minTestFiles, minTests}`      | 用例数随扫描结果变化、无法写死时改判**下界**（P2 契约扫描即用此项）；与上面精确值二选一                                                                   |
| `extraCommands`                          | 本批附加命令（如 P2 的 `pnpm test:contract`），`[{id, cmd, expectExit}]`，门禁逐条判 exit code                                                            |
| `baselineStatus`                         | **上一批验收通过时的 `git status --short` 终态**（原样，`XY\|path` 格式）                                                                                 |
| `allowedNewStatus`                       | 本批允许新增的状态行；人审自己新增的文档 / 脚本也要列进去                                                                                                 |
| `newTestFiles` / `forbiddenScanFiles`    | 前者扫 `// assert:`（含存量用例），后者扫禁用绕法（**只放本批新增**，避免误伤 P0 的 `data-testid` smoke）                                                 |
| `requiredSnippets` / `requiredSuffix`    | 本批的关键实现约定                                                                                                                                        |
| `mutations`                              | **本批核心**：每组至少一条 `{id, file, find, replace, minFailed}`；`find` 必须**全文件唯一命中**，脚本自动做「改实现 → 红 → 还原 → 绿 → `git diff` 为空」 |

`assertMaxDistance`（默认 10）控制连续 `expect` 组共用一条 `// assert:`
的追溯窗口； `build: true` 时脚本自动还原
`tsconfig.tsbuildinfo`（跑前不干净则 SKIP 并 FAIL，按 P0 复议 §10.2 纪律）。

## 2. 人审只做三件事

1. 看门禁 `PASS n/n` 与 **exit code** —— 绿即验完，**不再逐格读回执**。
2. 读回执的「期望值推导 / 口径差异披露」，裁定是改草案、记挂账，还是停机问人。
3. 抽查 1~2 处机器判不了的：业务语义是否合理、有没有**为凑绿缩小边界**。

> 门禁判不了「边界够不够」，只判「写出来的断言能不能红」。所以覆盖表仍由人定，这是唯一不能外包的部分。

---

## 3. 通用停机条件

1. 门禁要求改 `implementationFiles` 最终态 / 配置 / 工具链才能过；
2. 变异不红、还原不绿、`git diff` 非空；
3. 静态扫描命中禁用绕法（`vi.mock('fetch')`、mock 被测模块、导出私有函数等）；
4. 期望值从实现推不出来（缺口径）→ 停机写清卡在哪一行；
5. 任何越界文件、commit / push、后续批次动作、真实接口 / 线上配置写操作。
